# 새소리 참조 음원 소싱 계획

`03_소리기능_서버_GPU_구현계획_팀원.md` 8단계("참조 음원과 유사도")에서 요구하는 참조
음원 라이브러리를 만들기 위한 조사·도구 모음이다. 코드(0~7단계)보다 훨씬 오래 걸릴 수
있는 작업이라, 사용자 지시(2026-07-28)에 따라 0단계와 병행해서 지금부터 시작한다.

이 폴더는 `research/species-pool/`(기존 82종 도감 데이터 소싱 작업)과 같은 성격의
"콘텐츠 조사/준비" 공간이다 — 런타임 코드가 아니다.

## 왜 8단계를 마지막에 두면 안 되는가

8단계는 종당 검증된 구간 20개 이상·서로 다른 녹음 세션 5개 이상·혼동종 참조 포함·
라이선스 확인을 요구한다. 이건 코드 작업이 아니라 **콘텐츠 소싱 + 법적 검토**라 시간이
오래 걸린다. 0~7단계 코드가 다 끝난 뒤에 시작하면 "코드는 준비됐는데 음원이 없어서
게임을 못 띄운다"는 상황이 생긴다.

## 소스: Xeno-canto

**선택 이유**: 세계 최대의 크라우드소싱 새소리 아카이브, 전곡 Creative Commons 라이선스,
공식 API(v3) 제공, 종/국가/라이선스로 정밀 검색 가능.

**막힌 부분(사람이 해야 함, 내가 대신 못 함)**:
- API v3는 **계정 가입 + 이메일 인증 후 발급되는 API 키**가 필요하다. 자동 가입/이메일
  인증은 에이전트가 대신할 수 없다 — **사용자가 https://xeno-canto.org 에서 계정을 만들고
  Account 페이지에서 키를 발급받아야** `fetch_xeno_canto.ts`를 실제로 돌릴 수 있다.
- `xeno-canto.org` 웹사이트 자체는 봇 방지(Anubis)가 걸려 있어 스크레이핑으로 우회 조회가
  안 된다 — 오직 공식 API 경로로만 접근 가능하다(오히려 이게 더 안전한 방법이다).
- **API 자체가 "비영리 목적 무료"로 안내됨(rate limit 1000 req/hour)** — 이 앱이 유료화되거나
  광고가 붙는 등 상업적 성격을 띠게 되면 Xeno-canto API 이용약관을 다시 확인해야 한다.
  **(해결됨, 2026-07-28)**: 사용자가 앱을 현재 비영리로 확정함 — `docs/audio/DECISIONS.md`에 기록됨.

## 라이선스 정책 (2026-07-28 확정)

개별 녹음의 `lic` 필드가 `CC0`, `CC-BY`, `CC-BY-SA`, `CC-BY-NC`, `CC-BY-NC-SA` 중 하나인
것만 채택한다. `CC-BY-ND*`/`CC-BY-NC-ND*`(2차 저작물 금지 포함 전부)는 **계속 채택하지
않는다** — 표준 PCM 변환 파이프라인(Stage 3) 자체가 2차적저작물 소지가 있어 ND는 라이선스
종류와 무관하게 위험하다고 봄.

원래는 CC0/CC-BY/CC-BY-SA만 쓰려 했으나(NC/ND 전부 제외, "앱 성격이 바뀌어도 다시 정리할
필요 없게" 최대한 보수적으로), 실제 조회 결과 18종 중 12종이 0건이라 물리적으로 불가능해
NC를 포함시켰다(자세한 경위는 아래 "2026-07-28 진행 상황" 참고). **이 결정은 앱이 지금
비영리라는 전제에 의존한다** — 앱이 나중에 상업적 성격을 띠면 NC로 수집한 클립을 전부
재정리해야 한다(`clips.csv`의 `license` 컬럼으로 NC만 걸러낼 수 있게 원본 라이선스 URL을
그대로 남겨뒀다).

채택한 각 클립은 `attribution`(녹음자 이름 + 라이선스 + 출처 링크)을 반드시 앱 내
어딘가(예: 설정 > 저작권 정보)에 노출해야 한다(CC-BY 계열의 공통 요구사항).

## 목표 종(현재 seed 18종, `taxon_id` = 실제 도감 taxon ID)

`species_manifest.csv` 참고. 8단계 완료 기준(종당 20구간/세션 5개 이상)을 만족하는지
`status` 컬럼으로 추적한다.

## 2026-07-28 진행 상황: 정책 확정 후 18종 전부 목표치 확보

**1차 시도**(CC0/CC-BY/CC-BY-SA만): 18종 중 12종이 0건, 나머지도 종당 1~2건뿐이라 목표
(종당 20구간/세션 5개)에 한참 못 미쳤음 — 대부분 `CC-BY-NC-SA`(비영리 전용)였기 때문
(예: 까치는 97건 중 73건이 by-nc-sa).

이 결과를 사용자에게 보고하고 두 가지를 확인받음:
1. **라이선스 정책 — `CC-BY-NC`/`CC-BY-NC-SA`까지 포함(ND는 계속 제외)** 하기로 결정.
   앱이 지금 비영리로 확정됐기 때문(`docs/audio/DECISIONS.md` 2026-07-28 항목).
   **주의**: 앱이 나중에 상업적 성격을 띠면, `clips.csv`의 `license` 컬럼으로 NC 클립을
   걸러내 재정리해야 한다.
2. `taxon-sinosuthora-webbiana`(붉은머리오목눈이) 학명 문제 원인 확인: Xeno-canto가 이
   종을 `Sinosuthora webbiana`로 색인하는데, seed 데이터의 `sciName`은 `Suthora webbiana`
   라 검색이 0건이었음(taxonId 슬러그 자체는 이미 `sinosuthora`로 맞았음). 소싱용
   `species_manifest.csv`의 `sci_name`만 고쳐서 재조회했다 — `seedData.ts`의 `sciName`
   필드 자체를 고칠지는 아직 별도 결정 필요(이 소싱 작업과는 독립적인 이슈).

정책 반영 후 재조회 결과: **18종 전부 목표(20구간/세션 5개) 초과 확보**(최소 괭이갈매기
28구간·23세션, 최대 참새 89구간·73세션). `collected_sessions`는 (녹음자, 녹음일) 조합의
distinct 개수로 기계적으로 계산했다 — 사람이 실제로 들어서 "같은 세션인데 녹음자/날짜가
잘못 기록됐다" 같은 예외를 다시 확인할 여지는 있다.

**아직 사람이 해야 하는 일(내가 대신 못 함)**: `clips.csv`의 각 후보를 실제로 들어보고
① 정말 그 새 소리가 맞는지 ② 배경 소음/다른 종 혼입이 없는지 ③ `call_type`(현재 전부
기본값 `call`로 채워둠 — song/call/alarm 등 실제 종류로 재분류 필요)을 확인해
`quality_status`를 `pending → approved/rejected`로 바꾸는 것. 종당 20개를 다 들을 필요는
없다 — 후보가 넉넉하니(최소 23개) 승인 기준을 넘는 20개만 확보하면 된다.

## 혼동종(confuser) — 잠정, 검증 필요

아래는 분류학적으로 가까운 종끼리 묶은 **1차 추정**이다. 실제 "소리가 헷갈리는" 조합은
조류 음성학 전문 자료(예: 국립생물자원관, Merlin Bird ID 종별 설명)로 재검증해야 한다 —
내가 임의로 확정할 부분이 아니다.

| 그룹 | 종 |
|---|---|
| 오리류 | 청둥오리, 흰뺨검둥오리 |
| 백로류 | 왜가리, 대백로 |
| 박새류 | 박새, 쇠박새 |
| 까마귀류 | 큰부리까마귀, 까치, 물까치 |

## 진행 방식

1. **(사용자 필요)** Xeno-canto 계정 생성 + API 키 발급 + `.env`에 `XENO_CANTO_API_KEY` 채움.
2. **(사용자 필요)** 앱 상업성 여부를 `DECISIONS.md`에 기록(라이선스 정책 재확인용).
3. `npx tsx research/audio-reference-pool/fetch_xeno_canto.ts` 실행 — 종별 후보를
   조회하고, 라이선스 필터를 통과한 것만 `species_manifest.csv`에 채워 넣는다(오디오
   파일 자체는 Git에 넣지 않는다 — `research/audio-reference-pool/downloads/`는
   `.gitignore` 대상, CAMP-3의 참조 음원 캐시 디렉터리에 별도 보관).
4. 사람이 후보를 직접 들어보고 품질(target 종이 실제로 우세하게 들리는지) 확인 —
   `species_manifest.csv`의 `quality_status` 컬럼(pending/approved/rejected)으로 기록.
5. 종당 20구간·세션 5개를 채우면 그 종은 8단계 착수 가능.
